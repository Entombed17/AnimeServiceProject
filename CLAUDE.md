## Commands

Windows host — use the `.cmd` wrapper (in PowerShell: `.\mvnw.cmd`; from the Bash tool: `./mvnw.cmd`).

```powershell
.\mvnw.cmd spring-boot:run          # run the app (port 8081)
.\mvnw.cmd clean package            # build the jar
.\mvnw.cmd test                     # all tests
.\mvnw.cmd test -Dtest=SomeTest                 # one test class
.\mvnw.cmd test -Dtest=SomeTest#someMethod      # one test method
```

No linter/formatter is configured. Requires Java 21 and a running PostgreSQL with the `anime_tracker` database — the app fails to start without it.

## Architecture

Spring Boot 4.1 REST backend for an anime tracker. Currently **only the auth slice exists** — there are no anime/watchlist domain entities yet, despite the project name.

Package layout under `com.kenshin.animetrackerserver`: `controller` → `service` (interface) + `service.impl` → `repository` → `entity`, with `dto.request.*` / `dto.response.*` / `dto.common` for the wire types and `security` for the filter chain. Every service is declared as an interface in `service` and implemented in `service.impl`; follow that split when adding services.

### Auth flow

Stateless JWT, two token types with different mechanics:

- **Access token** — JJWT HS-signed, `subject` = the user's **email** (not the id or username), 15 min TTL. `JwtServiceImpl` reads `jwt.secret` / `jwt.access-token-expiration` from config.
- **Refresh token** — an opaque `UUID`, stored in the `refresh_tokens` table, 30 days. `RefreshToken` has a `@OneToOne` to `User` and `RefreshTokenServiceImpl` reuses the existing row per user, so a user has **at most one live refresh token** — a new login invalidates the previous session.

`SecurityConfig` permits `/auth/**` and requires authentication everywhere else; `JwtAuthenticationFilter` runs before `UsernamePasswordAuthenticationFilter`, extracts the email from the bearer token, loads the `User` and puts the **`User` entity itself** (no authorities) into the `SecurityContext`. So in a controller, `@AuthenticationPrincipal User user` is the way to get the caller.

### Conventions and known gaps

- Errors are thrown as bare `RuntimeException` in the service layer and there is no `@RestControllerAdvice`, so failures currently surface as 500s. Adding a global exception handler is a pending piece of work, not an established pattern to imitate.
- Schema is generated by Hibernate `ddl-auto: update`; there are no migrations, so entity edits are the schema.
- `AuthService` exposes only `register` and `login`. `refresh` / `logout` and the whole profile feature are unimplemented, though the profile DTOs (`UpdateProfile*`, `ChangePassword*`) already exist unused.
